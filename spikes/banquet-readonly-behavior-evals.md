# 婚宴只读行为回归

修复范围是已发布的 CRM Skill 协议：保留异步执行元数据、区分历史快照与当前交接、
在只读结果核验后结束本轮。账本、卡片回调、身份权限及工具接口不变。

`ops/banquet_behavior_eval.py` 固化四种已观察的失败决策，使用虚构编号和内容：
运行中的查询被重复发起；带读取时间的第8版历史快照被认定为当前第9版冲突；
只读核验失败接手回执后再次建卡；合并读取技能文档的输出已被截断，却继续调用
业务工具。后一次原生复验确认历史版本规则位于省略部分，既有模型诊断将完整协议
直接提供给模型，未覆盖这一加载失败。Skill 入口现在要求单独完整读取婚宴协议并
补齐截断内容；诊断追加下一步应继续读取协议的用例，实际加载仍需原生轨迹验证。
对照包括已完成查询、真实正文矛盾、正文未知、
下一轮明确要求接手、只解释引文。单元测试验证评分器能拒绝原失败，不能据此宣称
模型修复通过。模型诊断直接使用这份提交的协议，但只选择下一步，不运行业务工具。

PDF 只读核验还覆盖一次真实失败：提取两页中文后发现错序，工具可用却以限制说明
结束，没有渲染或读取页图。缺陷轨迹先按“选定原件哈希、渲染清单及实际返回页图”
判为失败，原记录保留在本地；本脚本仅保存虚构化决策场景。诊断现在加载文件生产
协议，检查乱码后先渲染、渲染后仍有未读页时继续检查，以及实际权限拒绝时保留限制
并停止。只读检查产生的预览不等于业务文件交付。真实复验应使用自然正文核对请求，
不在请求中提示渲染命令；核对同一原件、逐页返回、回答依据和无新增审批。

```powershell
python -m unittest discover -s tests -p test_banquet_behavior_eval.py -v
python ops/banquet_behavior_eval.py --codex <native-codex-executable> --output <new-jsonl-file> --repeat 3
```

诊断固定 `gpt-6-luna` / `medium`，沿用本机已登录的 CLI，不配置或复制认证；使用
临时目录、只读沙箱、关闭本机配置与项目规则加载。每条证据保存实际 CLI 版本、
协议哈希、结构化决策、原始答复和错误，意外工具调用判失败。不保存原始运行日志。
模型生成的解释仍需独立语义检查：结构化判据不能证明自然语言完全正确。

真实验收继续在授权的虚构婚宴及指定飞书入口中进行：核对同轮完整工具输出与等待
链，统计相同查询的启动次数，实际读取 Word/PDF，对照正文时间与宿主版本；只读
失败回执轮次关联宿主记录，确认没有新增审批卡。后续明确接手请求仍可正常建卡，
用宿主卡取消测试提案或完成用户要求的操作。旧策略的偶发错误不保证在简化决策
诊断里重现；保留原观察证据、所有诊断结果及实际复验结果，分别说明证据边界。
