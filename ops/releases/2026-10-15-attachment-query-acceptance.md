下表单位为秒；时间来自实际消息及工具记录，保留三个小数只表示原日志精度。
core 完成日志发生在最终回复发送之前，因此这里不是飞书最终送达耗时。

“其余 native 区间”由总区间减业务区间得到，不等于纯模型耗时。两边各读 3 份业务
规则；owner 多一次成功但多余的工具目录过滤，没有重现嵌套执行的错误工具调用。
业务区间包括进程等待及模型发起轮询间隔；授权、数据库锁、网络及纯模型耗时
无法再拆分。SDK 前缀只有秒级精度，平台最终交付时刻未知。

owner 查询 native 与 test 普通 PDF 处理重叠 11.831 秒，与报价 PDF 处理重叠
11.770 秒，合计 23.601 秒；其中普通 PDF 渲染尾部重叠 2.087 秒。
owner 业务命令期间实际只与另一账号规则读取重叠；另一账号后续 work-context
及渲染开始于查询完成之后。**未测到 Host 导入/激活授权或 SQLite 竞争区间**，
不能据此声称慢导入没有影响。每种条件仅一个查询样本，账号、上下文和负载不同，
无成对对照；不计算 P95，也不宣称性能改善。

批量附件同账号串行等待明显：扫描件、普通 PDF、报价 PDF、Excel 的 native

41.638、69.533、100.528、116.438 秒。后二者差额包含排队及编排，不能全标为数据库锁。
综合核对 native 100.920 秒、core 101.824 秒。综合完成到下一查询开始的
137.736 秒是操作者间隔，不计查询延迟。
