Status: runtime source delivery, three native cutovers and the third candidate's five targeted live read-only checks are complete. This documentation-only archive requires its own exact-head reviews and CI before merge. The second candidate's final owner read-only turn failed truncated-reference recovery; that failure is retained below. The shared Gateway reminder now explicitly covers read-only domain queries and complete, separate reference loading.

The controlled CRM protocol now preserves exec session metadata and polls a running query instead of repeating it. Banquet material checks distinguish dated source snapshots and file revision labels from current host versions. Each new turn determines read versus write intent afresh: reading a failed, expired or replan-required receipt does not stage another card. A later explicit acceptance request still uses the existing approval flow. No authorization boundary or business ledger rule changed.

A first native retest still misread the historical snapshot. Its combined seven-reference tool result was truncated before the new banquet rule, and the model did not reread that reference. The second change directs separate complete reference reads and recovery of truncated sections. This is model guidance, not a deterministic enforcement boundary.

## Evidence and limitations

Restricted evidence is retained in `banquet-behavior-evidence-20261013`. Public native traces include user messages, visible replies and tool calls/results; hidden reasoning is excluded and image payloads are deliberately omitted. Recorded document text/hash reads and image-view requests do not constitute an independent pixel-level certification of omitted images. Raw chats, private links, recipient identifiers, credentials and ledgers are not committed.

Some completed-read wrappers in both the second and third candidates still emitted only `output`, despite the protocol requiring the complete exec result. Those calls finished and did not repeat; the second candidate's real running-session case above retained metadata and polled correctly. The third candidate's receipt batch, owner queries and group queries retained full result metadata, but its recipient context/handoff wrappers did not. This residual protocol adherence risk is retained explicitly; future slow calls are not guaranteed safe by these finite observations. The second candidate's owner submit turn also read the complete banquet rule in a combined, untruncated result rather than a standalone one. More seriously, its final read-only turn at 15:08:17Z combined five references, returned two actual truncation warnings in a 28576-character result and omitted the material-history rule. Domain queries followed at 15:08:22Z without recovery. The collector did not truncate that result. This failed the separate complete-reference criterion despite no recurrence of the three original symptoms in that turn, and blocked the first archive review. The third-candidate replay corrected that observed failure; it does not erase it or establish universal compliance. Broader timeout, expired-receipt, quoted-intent and true-current-conflict cases remain automated/diagnostic coverage, not additional live runs.
